# /log-judgment $ARGUMENTS

SHIN の判断を記録シートに書く。**AI は下書きを整えるだけ。「判断の出所」は書かない。**

## 手順

1. `docs/記録シート.md` §1 を読む。引数が `next` または空なら最終行の次の番号を使う。指定された J-ID が既にあれば、その行の更新として扱う
2. 直前の会話に `record-judgment` の下書きがあればそれを使う。無ければ、次の5点を **1回の質問でまとめて** SHIN に聞く:
   - 工程(§2-1 の13工程から)/ 範囲(Dir・Des・Code・UX)
   - AI の初案(何を出したか)
   - 自分の判断(採用 / 却下 / 条件追加 / 自分で決定 + 内容)
   - 修正後
   - 対応章(1〜6 または —)/ 証拠
3. §1 の表の **最終行の直後** に行を追加する。空の `| J-NNN | | | ...` 行があればそれを置き換える。列順:
   `| ID | 日付 | 工程 | 範囲 | AIの初案 | 自分の判断 | 判断の出所 | 修正後 | 対応章 | 証拠 |`
   **「判断の出所」は空欄で書く。**
4. 「これは大きな判断か(後続の設計を縛るか)」を1行で聞く。Yes なら `docs/templates/decision.md` から `docs/decisions/J-NNN.md` を作る。同じく「判断の出所」と「この条件で効く」は空欄
5. AI の誤りが含まれる場合は §3 に F-ID の行も追加する(何が起きたか / なぜ気づけたか / どう直したか / 学び / 対応章)
6. スクショが関係するなら、仮名ファイルの改名を促す:`docs/screenshots/J-NNN-before.png` / `-after.png`
7. 最後に、次に使うコミット件名の例を1行出す:`feat: <subject> [J-NNN]`

## 書き込み後に出す確認

```
記録シート §1 に J-NNN を追加(判断の出所:未記入)
decisions: あり / なし
F-ID: あり(F-NNN)/ なし
スクショ: 改名待ち / なし
次のコミット: feat: ... [J-NNN]
```

## やってはいけないこと

- 「判断の出所」を埋める・例文を入れる
- SHIN が言っていない理由を補う
- 記録シートの他の行・他の節を書き換える
- 「そのまま採用」の案件に J-ID を付ける(その場合は §1 直下の「そのまま採用」表に1行追加する)
