# interface-design スキルの使い方(2026-09-19)

`.claude/skills/interface-design/` の運用ルール。**このファイルはパスに紐づけず、必要な時に指示文で名前を指定して読む**(`rules/search.md` などと違い、自動では読み込まれない)。

スキル本体は `0dd9939` に入っている(J-118 と同じコミット。経緯は記録シート §1 の「J-ID を付けなかった修正」)。

## 1. いつ使うか

**03 に無い観点を評価する時**に使う。具体的には次の3つ。

- **文字の階層**(どの段が何を担っているか。03 §4 はサイズの表だが、階層の効き方は書いていない)
- **密度のリズム**(詰める所と空ける所の交互。03 §5 は余白スケールだが、リズムは書いていない)
- **焦点の置き方**(画面に入った時にどこを最初に見るか)

出力は **すべて初案**として扱う(`rules/record-keeping.md` §1)。スキルが「こうすべき」と書いていても、それは初案であって決定ではない。

## 2. 03 と衝突する項目は 03 が優先

スキルの一般論より、このサイトの決定が先。**次の4点は衝突するので、スキルの指示に従わない。**

| スキルの記述 | このサイトの決定 | 出所 |
|---|---|---|
| native の `<select>` / `<input type="date">` は使わず独自部品を作る | **native を使う**。フォーム4本のセレクト(区・間取り・時期・時間帯)と日付は native のまま | J-107・J-108(実装)・J-102 c(フォームの骨格)。独自部品にすると読み上げ・キーボードの経路を作り直すことになり、J-110〜J-112 で整えた形を壊す |
| データ(数字・ID・日時)は monospace に | **書体は Noto Sans JP 1種のみ**。数字は同じ書体の 700 + `tabular-nums` で揃える | 03 §3(「1種のみ」「2書体目」は §8 やらないこと) |
| ダークモードの設計(影より枠線・彩度を落とす 等) | **ダークモードは無い**。面は 白 / 薄灰 の2つだけ | 03 §2 |
| hover・押せるものの見た目の作り方 | **03 §6「押せるものの見た目」に従う**(押せるチップ = 白地+青緑の細枠+青緑の文字 / 押せる文字 = 下線)。hover の扱い(150ms・`prefers-reduced-motion` で無効)も 03 §8 | 03 §6(J-052 → J-096 → J-115)・§8 |

判定に迷ったら **03 §10 の A / B / C** で分ける。スキルの指摘が 03 の不備を突いているなら **B(基準の不備)**として 03 を先に直し、版を上げてからページを直す。

## 3. `.interface-design/system.md` は作らない

スキルは「プロジェクトに `system.md` を作って決定を記録する」形を持っているが、**このプロジェクトでは作らない**。パターンの記録先は `docs/03-デザイン基準.md` の1箇所にする。

理由:**2箇所に規則を持つと、片方だけ直る**。03 は §11 に版と J-ID の履歴を持っており、判断の出所を追えるのはこちら。`system.md` を置くと、記録(このプロジェクトの成果物)が二重になる。

スキルが `system.md` を読もうとした時は「無い」として扱い、決定が要る項目は **03 に書いて版を上げる**。
