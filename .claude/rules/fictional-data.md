# 架空データのルール(会社設定・シード・JSON・WP プラグイン)

このサイトの会社・物件・人物はすべて架空。**実在と衝突する値を1つも作らない。** 値を書く前に `web/src/config/site.ts` と `docs/02-物件データ設計.md` を読む。

## 1. 固定書式(例外なし)

| 項目 | 書式 | 禁止 |
|---|---|---|
| 番地 | `0-0-0`(例:東京都葛飾区青戸0-0-0) | 実在しそうな番地 `2-15-3` 等 |
| 電話 | `03-0000-0000`(本店)/ `03-0000-0001`(立石店) | それらしい番号 |
| 免許番号 | `東京都知事(5)第000000号` | 連番・実在番号 |
| 所属団体 | 「(架空)」と表記 | 実在団体名(保証協会・宅建協会等) |
| 人名 | 姓は **架空 / 見本 / 仮名** のみ。8名は `docs/01-設計図.md` 末尾の表 | 実在しうる姓 |
| 物件名 | `{町名}{ハイツ|コーポ|レジデンス|メゾン|テラス|ハウス}0-{数字}`(例:青戸ハイツ0-3) | `0-` の無い名前 |
| 物件番号 | `HR-R-0001`(賃貸)/ `HR-S-0001`(売買) | |
| 住所 | `東京都{区}{町}0-0-0` | 町域外の地名 |
| LINE | 「LINE(ダミー)」表記。リンク先は説明ページ | 実在アカウント風のリンク |
| 架空注記 | 最上部バー・フッター・会社概要・宅建業法表示・フォーム上部/完了/自動返信に「このサイトは制作記録用の架空サイトです」 | 省略 |

- 営業時間 9:30〜18:30 / 定休日 水曜 / 管理戸数 800戸 / 入居率 96%

集約先は `web/src/config/site.ts` の1ファイル。**18ページに散らすと1箇所だけ実在っぽい番号が残る事故が起きる**(制作計画 §8-2)。

座標は `docs/02-物件データ設計.md` §8-1 の代表座標 ±0.004 度。実在建物に一致させない。

## 4. シード(`web/scripts/seed/` と `wp/plugins/hr-core/scripts/seed-*.php`)

- 件数:賃貸40 / 売買20。配分・分布は `docs/02` §6 の表のとおり
- **乱数に相関を持たせる**:間取り×面積 / 築年×設備 / 駅徒歩×家賃。独立乱数(1R で 90㎡、築2年でオートロックなし)は誤り
- **意図的な欠損を作る**:写真0枚 3件 / 成約済み 8% / 商談中 12% / 値下げ 賃貸5・売買3 / 14日以内の新着 10件前後
- ステータスは `open / negotiating / sold` の3値。**新着(公開日から14日)と値下げ(前回価格との比較)はフィールドから導出**し、タクソノミーに入れない
- 写真はプレースホルダー(単色 + 物件番号 + 種目名)。実写真・AI 生成画像は使わない
- **WP を経由する**。JSON を直接書かない(実案件の経路:管理画面 → REST → JSON)
- 担当者コメントは冒頭・中間・末尾の各4パターンの組み合わせ。実在の店名・施設名を入れない

## 5. 出力前チェック(このパス配下を編集した時に必ず行う)

1. `0-0-0` / `0000` / `000000` 以外の番地・電話・免許番号が無いか grep する
2. 人名の姓が 架空・見本・仮名 以外に無いか
3. 地名・駅・沿線が §3 の一覧の中か
4. 「架空」の注記が消えていないか

違反があれば直す前に SHIN に報告する(AI の初案が架空ルールを破った事実は F-ID の候補)。
