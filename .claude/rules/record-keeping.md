# 記録運用ルール(全ファイル共通)

このプロジェクトの成果物はサイトではなく **記録** である。以下は常に適用する。

## 1. 初案の明示

- AI が設計・コード・文言・デザインの案を出す時は、冒頭に **「これは初案」** と書く
- 公式スキル(`react-best-practices` / `web-design-guidelines` / `webapp-testing`)や Claude Design が出した案も初案として扱う
- 初案は1つ出す。代替案は「文章で1行」に留め、描かない・実装しない

## 2. J-ID の採番(判断ログ)

**記録するのは判断が発生した瞬間だけ。** 以下のどれかが起きた時に J-ID を採番する。

| 起きたこと | 記録 |
|---|---|
| SHIN が AI の案を却下した | J-ID |
| SHIN が条件を足して出し直させた | J-ID |
| AI が出せず、SHIN が自分で決めた | J-ID |
| AI の出力が間違っていて SHIN が気づいた | J-ID + F-ID(記録シート §3) |
| AI の案をそのまま採用して問題なかった | 「そのまま採用」1行のみ(J-ID なし) |

手順:
1. `docs/記録シート.md` §1 の最終行から次の番号を決める(欠番を作らない)
2. §1 に下書き行を追加する。列:ID / 日付 / 工程 / 範囲(Dir・Des・Code・UX)/ AI の初案 / 自分の判断 / **判断の出所(空欄)** / 修正後 / 対応章(1〜6 または —)/ 証拠
3. 大きな判断は `docs/templates/decision.md` から `docs/decisions/J-NNN.md` を作る
4. **「判断の出所」列は AI が埋めない。** SHIN が書く。AI が埋めると自己申告が推定に変わる
5. 「自分の判断」列は SHIN の言葉をそのまま要約する。AI が理由を補わない

## 3. スクリーンショット

- 置き場所:`docs/screenshots/`
- 命名:`J-NNN-before.png` / `J-NNN-after.png`。同じ判断に複数ある時は `-before-2` `-after-2`
- 撮る対象:デザイン初案・崩れた表示・エラー画面・AI の初案そのもの。**撮り逃すと復元不可**
- J-ID が決まる前の初案は仮名(`design-v0.1-01.png` 等)で保存し、採番後に改名する。AI は採番時に改名を促す

## 4. コミット規約

- 英語・Conventional Commits:`feat:` `fix:` `docs:` `refactor:` `chore:` `style:` `test:` `perf:` `ci:` `build:`
- **判断を伴うコミットは件名末尾に `[J-NNN]`**。判断を伴わないコミットには付けない
- 記録が先、コミットが後。`[J-NNN]` を付ける前に記録シート §1 の行が存在すること(hook が検査する)
- 1コミット1判断が原則。複数の判断をまとめない

## 5. 失敗記録(F-ID)

AI が間違えて SHIN が気づいた時は記録シート §3 に F-ID で追加する。列:何が起きたか / なぜ気づけたか / どう直したか / 学び / 対応章。
地名・沿線・駅・施設名は AI が間違えやすい。出力前に `docs/02-物件データ設計.md` §8 の 13 町・13 駅・6 沿線と突合し、一覧に無いものは使わない。

## 6. 実測

- 実働時間は `docs/progress/time-log.md` にセッション単位で SHIN が記録する(自己申告)。AI は行を作らない
- AI が書けるのは裏付け(コミット時刻・会話の時刻)への言及だけ
- 初案の数 / そのまま採用 / 修正して採用 / 却下 / 手戻り回数は週次ログでまとめる。AI は週次ログの下書きを作ってよい

## 7. 書き方の癖(このプロジェクトで2回指摘された)

- **反証は結論の位置に置かない。** 結論を先に書き、「この条件で効く / 効かない」の形で後ろに置く
- 「〜と思われます」「一般的には」で埋めない。**推測で埋めず、実物(`docs/`・リポジトリ・公式ドキュメント)を先に読むか、SHIN に聞く**
- 断定できない箇所は「未確認」と書く

## 8. 記録しないもの

ツールの操作手順、ファイルの置き場所、AI の生成待ち、AI が自分で直した typo。判断ではないものは記録シートに入れない。
