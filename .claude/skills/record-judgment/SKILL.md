# 判断ログの下書き(record-judgment)

このスキルは **AI が判断の発生に気づいた時に自動で使う。** 実際に記録シートへ書き込むのは `/log-judgment`(SHIN が呼ぶ)。ここでは下書きだけ出す。

## いつ発動するか

会話の直前で次のどれかが起きた時。

- SHIN が AI の案を **却下** した
- SHIN が **条件を足して** 出し直させた
- AI が出せず、SHIN が **自分で決めた**
- AI の出力が **間違っていて SHIN が気づいた**(この場合は F-ID も)

「AI の案をそのまま採用した」時は発動しない。代わりに「そのまま採用」1行を提案する。

## 手順

1. `docs/記録シート.md` §1 を読み、最終行の ID から次の番号を決める(例:J-024 → J-025)
2. `docs/templates/decision.md` を読み、列構成に合わせる
3. 下書きを **チャットに** 出す(ファイルはまだ書かない)。形式:

```
【判断ログ 下書き】J-NNN(これは下書き。判断の出所は空欄)
| J-NNN | MM/DD | 工程 | 範囲 | AIの初案 | 自分の判断 |  | 修正後 | 対応章 | 証拠 |
スクショ:あれば docs/screenshots/J-NNN-before.png / -after.png に改名
F-ID:AIの誤りなら F-NNN の行も併記
→ 確定するなら /log-judgment J-NNN
```

4. 列の埋め方
   - **工程**:記録シート §2-1 の13工程名から選ぶ(要件定義・会社設定 / サイトマップ・ページ設計 / デザイン基準の策定 / デザイン(各ページ)/ WP側 / Next.js側 / 検索・絞り込み / 地図連携 / フォーム / スマホ対応・実機確認 / 公開 / 速度改善 / 記録の整理)
   - **範囲**:Dir / Des / Code / UX(複数可)
   - **AI の初案**:何を出したかを1〜2文。自分を弁護しない
   - **自分の判断**:SHIN の言葉をそのまま要約(採用 / 却下 / 条件追加 / 自分で決定 のどれかを先頭に)
   - **判断の出所**:**空欄のまま**。SHIN が書く
   - **修正後**:決まった形を1文
   - **対応章**:1〜6 または —
   - **証拠**:本チャット / コミット / スクショ名
5. 大きな判断(後続の設計を縛るもの)なら「decision ファイルも作るか」を1行で聞く

## やってはいけないこと

- 「判断の出所」を書く・推測する・例を入れる
- SHIN が言っていない理由を「自分の判断」に足す
- 発動した事実を長く説明する。下書きを出して終わる
- 記録シートを直接編集する(それは `/log-judgment` の仕事)
