# 03 デザイン基準(v0.10 / 2026-09-09)

**これは初案。** 色(J-028)とフッター(J-027)は決定済み。それ以外は SHIN の判断待ち。
全ページはこの1枚から派生させる。ページごとに色や余白を足さない(章2「ページごとに雰囲気が変わる」を止めるため)。
対象:スマホ 390px を先に設計し、PC 1280px に展開する。

---

## 1. トーン

- **信頼感・清潔感**。25年やっている地元の会社が「ちゃんとしている」ことを、写真ではなく **書体・余白・情報の順序** で出す
- 主役は物件検索と物件情報。装飾は入れない。イメージ写真は使わない(プレースホルダーのみ)
- 参考にしたもの:LIFULL HOME'S(検索の入口・条件の並び・カードの情報順)/ 住宅ファミリー社(フッター)。外したもの:右カラム・ランキング・記事・通知・写真主体のレイアウト

## 6. 部品

**ボタン**

| 種類 | 見た目 | 用途 |
|---|---|---|
| 主 | 青緑背景・白文字・高さ 48(スマホ)/ 44(PC)・全幅(スマホ) | 検索・内見予約・査定依頼・相談 |
| 副 | 白背景・墨の1px枠・墨文字 | 詳細を見る・条件をクリア |
| 電話 | 墨背景・白文字・電話番号を表示 | ヘッダー・固定CTA。営業時間の併記は PC ヘッダーのみ(J-029) |
| リンク風 | 青緑(暗)・下線 | 「駅から探す」等の脇の導線 |

**アイコン**:lucide-react・20px・currentColor(親の文字色を継承)。線幅は既定。装飾には使わない

**絞り込み欄(左カラム・ドロワー)**:項目の文字は本文より1段小さい「小」13px、区名・沿線名の小見出しは「最小」11 / 12px。「エリア」「駅」などの見出しは H3 のまま。チェックボックスは項目文字と同じ高さ(13px)。セレクトは 13px・高さ 40(スマホ)/ 32(PC)・余白 8(チップと同寸。§6 フォーム入力の 46 は本文中のフォーム用)。絞り込み欄の部品(チップ・チェック・セレクト)は hover / active に 150ms・cubic-bezier(0.4,0,0.2,1) のトランジション(§8 の範囲内・J-035)。チップは hover で枠・文字が青緑+背景を淡い青緑 `#E0F2F1`(§2 新着バッジの背景と同じ段。選択中の濃い塗りとは区別)、チェック(ラベル含む)・セレクトは枠を一段濃く(灰)+背景を同じ淡い青緑。いずれも cursor: pointer。focus の輪郭は変えない。prefers-reduced-motion では無効(J-035)

**チップ(トグル)**:角丸 6px・高さ 40(スマホ)/ 32(PC)・13px・内側余白 8(J-035)。選択中は青緑の塗り+白文字、未選択は灰線の枠+墨文字。駅フィルターに使う(沿線ごとに横流し・複数路線の駅は重複表示可・J-034)

**フォーム入力**:高さ 46・枠 `#D9DDE1`・focus は青緑 2px。ラベルは上・13px・灰。必須は「必須」の文字(赤の * は使わない)。エラーは入力の下に赤文字で「何が・どう直すか」。

**物件カード(情報の順序・上から)**
1. プレースホルダー(比率 3:2)。バッジは左上に最大2つ
2. **家賃 / 価格** — 最大(管理費は詳細ページで。一覧サブセット index.json に持たない・J-033)
3. 間取り・面積
4. 最寄駅と徒歩分
5. 築年(階は詳細ページで・J-033)
6. 物件名 — 最小・灰
成約済みはカード全体を 60% に落とし、バッジで明示。一覧では成約済みを出し、並びは常に末尾(J-033)。
**カードは全幅で縦型1種類(画像上・文字下)。列数のみ幅で変える**:〜767px 1列 / 768〜1023px 2列 / 1024px〜 2列+左カラム(J-033・375px と 974px の実機確認で横型から変更)。

**基本情報表(詳細)**:2列、見出し列は薄灰。取引態様・物件番号・情報更新日・次回更新予定日を必ず含む。

## 7. レイアウトの型

- **ヘッダー**:白。ロゴ / メニュー5 / 電話(営業時間付き)。スマホはロゴ+電話+ハンバーガー。**スマホの電話ボタンは電話番号のみ(営業時間は出さない・J-029)**。メニューはオーバーレイで開く。スクロール後は高さを詰めて固定
- **架空注記バー**:最上部。墨背景・白文字 11px・全ページ
- **FV(トップ)**:決定済み。キャッチ+検索フォーム(タブ・3項目・青緑ボタンに件数)。画像なし
- **セクション**:白と薄灰の帯を交互に。見出しは H2 左寄せ、右に「すべて見る」リンク
- **一覧**:切替点は md(768)/ lg(1024)の2段。〜767px:縦型1列・絞り込みはドロワー(J-030 前提)。768〜1023px:縦型2列・左カラムなし・「絞り込み」ボタン+ドロワー・固定 CTA はそのまま。1024px〜:左に絞り込み(常時)+ 右にカード2列(J-033)。左カラムはヘッダー直下に sticky、高さの上限は「画面高 − ヘッダー高 − 16」、超える分はカラム内でスクロール(細いスクロールバー・J-034)
- **詳細**:ギャラリー → 物件名・価格・バッジ → 主CTA → 基本情報表 → コメント → 地図 → 関連4件 → 主CTA → 最近見た物件
- **スマホ固定CTA**:下部。3ボタン:電話 / LINE(ダミー)/ 内見予約(右端・J-030)。青緑は内見予約だけ。バーの高さ分の下余白を本文末尾に確保
- **フッター(J-027)**:墨背景・白文字。左に会社情報(2店舗・営業時間・架空注記)、サイトマップ5列(探す / サービス / 会社案内 / お知らせ / お問い合わせ)、矢印リンク2本(物件を探す / オーナー様へ)、最下段に著作・プライバシー・宅建業法表示。スマホは見出し5つのアコーディオン(details/summary・初期は閉・右端に ∨)。PC は5列。PC 右端に固定の縦タブ「物件を探す」(**墨背景・白文字・J-029**)
- **BtoB(オーナー向け)の切替**:(判断ポイント)色は変えず、見出しの文言と CTA(「管理のご相談」)だけ変える案 / 面の色を薄灰に反転する案

## 8. やらないこと

グラデーション / 影の多用 / 角丸の大小混在 / 青緑を装飾に使う / 純黒 / イメージ写真 / 2書体目

アニメーション:開閉・表示切替の 150〜200ms のトランジションは可(イージングは cubic-bezier(0.4, 0, 0.2, 1)。開閉 200ms・hover 150ms。prefers-reduced-motion では無効・J-035)。一覧の更新は 300ms(開閉の 150〜200ms とは別枠)。新規カードのみ、不透明度 0→1 + 8px 上昇 + 順番ずらし 30ms × 最大8(最大遅延 210ms)。残るカードは維持・消えるカードは即時・並び替えはアニメーションなし・0件表示は現れる時に1回。件数の数字が変わった時は青緑 → 通常色へ 300ms。外枠の作り直しはしない。位置移動(FLIP)は入れない(J-036)。ページ遷移・スクロール連動・装飾の動きは不可(J-031)

## 10. 手直しの型(初案は一発で決まらない前提)

1ページにつき「初案 → 判断 → 修正」が1〜3往復出る。往復の回数そのものが章2・章6の実測なので、減らすことより**記録すること**を目標にする。

**手直しは3種類。直す前にどれかを判定する。**

| 種類 | 例 | やること | 記録 |
|---|---|---|---|
| **A. 基準違反** | この基準に無い色・スケール外の余白・純黒・2書体目 | 基準を守るよう直させる。基準は変えない | AI の誤り → F-ID(気づいた手段を書く) |
| **B. 基準の不備** | 基準どおりに作ったらスマホで詰まる・読めない | **この基準を先に直し、版を上げてから**ページを直す。他ページにも効く | J-ID(条件追加)。基準の変更履歴を末尾に残す |
| **C. ページ固有の調整** | CTA の位置・見出しの文言・このページだけの並び | ページだけ直す | J-ID(却下 / 条件追加)か「そのまま採用」1行 |

B と C の区別が肝。C だと思って直したものが B(他ページでも出る)だと、後で全ページを触る。**迷ったら B 扱いで基準に書く。**

**1ページの流れ**
1. `/build-page` で初案 → before スクショ(スマホ・PC)を `docs/screenshots/` に
2. 判断ポイントと気になる点を A / B / C に分けて番号で返す
3. `/log-judgment` で記録 → 直させる → after スクショ
4. 2往復で収まらない項目は「AI に頼んでも直らない箇所」(章6)として記録し、手で直すか、置いて先に進む
5. コミット `feat: add <page> [J-NNN]`

**往復を増やさないために**
- 1往復目は構成と情報の順序だけ見る。色や 1px は2往復目
- 細かい調整を1つずつ J-ID にしない。1ページ 1〜2 件の J-ID に条件を箇条書きでまとめる
- 実装順 0(土台)で、ヘッダー・フッター・カードを実データで**わざと崩す**(長い物件名・写真0枚・成約済み・6枚)。ここで B を潰すと、以降は C だけになる
- 実装順 0〜3 は往復が多くて正常(基準の不備が出る時期)。4 以降は減る
