# 03 デザイン基準(v0.89 / 2026-09-19)

**これは初案。** 色(J-028)とフッター(J-027)は決定済み。それ以外は SHIN の判断待ち。
全ページはこの1枚から派生させる。ページごとに色や余白を足さない(章2「ページごとに雰囲気が変わる」を止めるため)。
対象:スマホ 390px を先に設計し、PC 1280px に展開する。

## 1. トーン

- **信頼感・清潔感**。25年やっている地元の会社が「ちゃんとしている」ことを、写真ではなく **書体・余白・情報の順序** で出す
- 主役は物件検索と物件情報。装飾は入れない。イメージ写真は使わない(プレースホルダーのみ)
- 参考にしたもの:LIFULL HOME'S(検索の入口・条件の並び・カードの情報順)/ 住宅ファミリー社(フッター)。外したもの:右カラム・ランキング・記事・通知・写真主体のレイアウト
- **情報の優先順位(J-039)**:関心の高い情報は、価値の薄い情報と同列に並べない。詳細のポイントタグ(最大3・データから導出)、一覧カードの4項目のように、先に判断できる形で切り出す。タグの語は絞り込み条件と同じ語彙を使い、データにない形容(閑静・人気 等)は使わない

**絞り込み欄(左カラム・ドロワー)**:項目の文字は本文より1段小さい「小」13px、区名・沿線名の小見出しは「最小」11 / 12px。「エリア」「駅」などの見出しは H3 のまま。チェックボックスは項目文字と同じ高さ(13px)。セレクトは 13px・高さ 40(スマホ)/ 32(PC)・余白 8(チップと同寸。§6 フォーム入力の 46 は本文中のフォーム用)。絞り込み欄の部品(チップ・チェック・セレクト)は hover / active に 150ms・cubic-bezier(0.4,0,0.2,1) のトランジション(§8 の範囲内・J-035)。チップは hover で枠・文字が青緑+背景を淡い青緑 `#E0F2F1`(§2 新着バッジの背景と同じ段。選択中の濃い塗りとは区別)、チェック(ラベル含む)・セレクトは枠を一段濃く(灰)+背景を同じ淡い青緑。いずれも cursor: pointer。focus の輪郭は変えない。prefers-reduced-motion では無効(J-035)

**チップ(トグル)**:角丸 6px・高さ 40(スマホ)/ 32(PC)・13px・内側余白 8(J-035)。選択中は青緑の塗り+白文字、未選択は灰線の枠+墨文字。駅フィルターに使う(沿線ごとに横流し。複数路線の駅は config の lines 順で最初の沿線にだけ置く・重複なし・J-034)

**絞り込み欄の構成(PC 左カラム・ドロワー共通・J-034)**:常時表示 = エリア / 駅 / 家賃(価格)/ 間取り(種目)。「詳細条件」(details・初期は閉・選択中の件数を見出しに)= 駅徒歩 / 築年数 / 面積 / 設備・条件。設備は 02 §2 の順で上位6つを表示し、残りは「もっと見る」で展開。折りたたみの状態は URL に入れない。余白:左カラム内側 12(カード内と同じ段)、チップの横間隔 4・チェック項目の横間隔 12(縦は 8 のまま)。エリア・間取り・設備のチェックは横並び折り返し(J-034)

**フォーム入力**:高さ 46・枠 `#D9DDE1`・focus は青緑 2px。ラベルは上・13px・灰。必須は「必須」の文字(赤の * は使わない)。エラーは入力の下に赤文字で「何が・どう直すか」。

**物件カード(情報の順序・上から。J-046 で 4項目 → 7項目)**

- 賃貸 = 交通(補足に町)/ 家賃(補足に 敷2・礼1・仲1)/ 間取り・専有面積(補足に築年・J-063)

誇張を避ける条件は a 種別ごとに項目固定・欠損は「—」 b 値のみ・形容は付けない、の2つを引き継ぐ。c「本文より1段だけ」は横一列に5項目を詰める前提が無くなったので外す(J-059)。

**旧仕様(J-047・v0.21〜v0.36。経緯の記録)**:見出し直下に**キー項目のカード**(白・角丸 6・灰線・影なし。セクションの薄灰の上に置く。PC は5等分のグリッドでセル間に細い縦線、高さ 80px 前後。スマホは2列×3行で区切りは横線のみ)。各セルは ラベル(最小・灰・左に lucide 16px)+ 値(H3)を左揃えで上下に。アイコン:家賃・価格 = JapaneseYen / 初期費用・管理費修繕 = Receipt / 面積 = Square / 築年 = Calendar / 最寄駅 = TrainFront / 土地権利 = FileText(J-047)。賃貸 = 家賃(管理費を小さく併記)/ 初期費用(敷2・礼1・仲1)/ 専有面積 / 築年 / 最寄駅 徒歩分。売買 = 価格 / 面積(マンション=専有、戸建=土地・建物、土地=土地)/ 築年(土地は —)/ 最寄駅 徒歩分 / 5項目目は マンション=管理費・修繕積立金(月額を合算せず「管理費 1.2万円 / 修繕 0.8万円」)、戸建・土地=土地権利(J-047)。誇張を避ける3条件:a 項目は全物件で固定・欠損は「—」 b 値のみ・形容は付けない(評価はポイントタグ) c 文字は本文より1段(H3)だけ・ラベルを必ず付ける。その下の**基本情報表**:4区分(基本 / 費用 / 建物 / 契約・掲載)の小見出し H3、区分の間は 24。**枠線・ラベル列の背景色なし。項目間は細い横線1本**。ラベルは 小 13px の灰、値は本文色・通常の太さ。ラベル列幅 112(スマホ)/ 144(PC)。PC(lg 以上)は左右2ペア×1行、スマホ・タブレットは1列。「設備」は非操作チップ(駅チップと同じ見た目・高さ 32)。取引態様・物件番号・情報更新日・次回更新予定日を必ず含む。初期費用は隠さず1行(価格直下の1行と二重表示を許容・J-038)。

**情報表の文字(J-090 の修正)**:**ラベルと値は同じ大きさ(小 13px)にし、差は色と太さだけで付ける**。ラベルは灰 `#5F6B75`・通常の太さ、値は墨 `#1F2933`・通常の太さ(「なし」「不要」と保証人だけ太字・J-054 / J-055)。値をラベルより大きくすると、値だけが浮いて表が読みにくくなる。
情報表は読み物ではなく**確かめるための表**(1物件で 14〜21行)なので、値も「小」に含める(§4 の用途に追記)。値を本文(15 / 16px)に上げる案は、「建ぺい率 / 容積率」が 16px で約 150px になりラベル幅 120px(7.5em)に収まらず、ラベル列を 10em まで広げることになるので採らない。
**例外は作らない。「入居時の目安合計」の金額も他の行と同じ「小」にする**(本文サイズにすると 13px のラベルとベースラインが 1〜2px ずれ、その行だけ揃っていないように見える)。合計を目立たせるのは**太字と上の区切り線**で足りる。

**列の使い分け(J-090 の実測から。1列 → 2列 → 1列と3回往復したので規則にする)**:
- **順番に意味がある情報は1列**。上から順に読む前提の並びを2列に流し込むと、読み順が「左の下 → 右の上」に折り返して壊れる。「入居前に確認すること」は**時点順**(毎月 → 最初に必要 → 更新時 → 入居時の目安合計)で、**合計は前の3つを足した結果**なので順番に意味がある。だから1列にする
- **並列の属性は2列**。「建物」(所在地 / 交通 / 沿線 / 築年月 / 構造 / 階数 / 向き)と「契約・掲載」は、どれを先に読んでも意味が変わらないので2列で成立する
- 迷った時は「**この並びを入れ替えたら意味が変わるか**」で判定する。変わるなら1列、変わらないなら2列。**幅が余っているかどうかでは決めない**(1列化を撤回した J-090 の原因がこれだった)

**情報表の線の引き方(J-088 → J-090 → J-090 の修正で3回再発したので規則にする。2026-09-14 の実測に基づく)**:線は**次の3種類だけ**。1280px・3つとも開いた状態で **20本**(アコーディオンの上線3 + 最後のアコーディオンの下線1 + 行の下線15 + 合計行の上線1)。
1. **アコーディオンの上線**(各区分の `border-t`)と、**最後の区分だけ下線**(`last:border-b`)…… 区分の境目はここだけで作る
2. **行の下線**(`border-b`)…… ただし**各列の最終行には引かない**。並びの終わりは 1 の線が示す
3. **合計行の上線**(1区分に1本まで)…… 意味が変わる所の区切り。**その直前の行は下線を引かない**

**この3種類以外に線を足さない。** 再発した3回はいずれも「行の最終行の下線」と「1 または 3 の線」が 12〜17px 離れて並び、2本に見えたもの。
**数え方**:2本の線の y の差が 20px 未満で、かつ x の範囲が重なっていれば二重。**左右の列の線は x が違うので二重ではない**(同じ y に2本並ぶのは正常)。**閉じたアコーディオンの中の行は箱としては測れるが描画されない**ので、`checkVisibility()` で除いてから数える(除かないと初期状態で4〜5件の誤検出が出る)。
**余白で区切る所に線を足さない。線で区切る所に余白を足さない**(J-088)。

**物件データ(J-060 → J-070 → J-074 → J-076)**:セクションの見出しは**「物件データ」**(J-076。概要は右カラムが担い、ここは数値と条件の置き場)。中身は**同列のアコーディオン3つ**で、見出しの階層は1つだけにする:**確認 → 建物 → 契約・掲載**(売買は 確認 → 土地・建物 → 掲載)。設備は右カラムへ移した(J-074)。**初期状態は確認だけ開き、他の2つは閉じる**(J-076)。見出しから1つ目までは 16。決め手は右カラムに集約したので、物件概要には置かない(J-070。J-047 の帯・J-059 の3項目は廃止。経緯は下の「旧仕様」に残す)。
1 **確認**:「入居前に確認すること」(売買は「購入前に確認すること」)。初期状態で開く。**中身はお金だけ**。**まとまりの見出しは置かず、1列に時点の順で並べる**(J-090 の修正)。賃貸 = 管理費・共益費 → 駐車場 → 敷金 → 礼金 → 仲介手数料 → 更新料 →(区切り)→ 入居時の目安合計、売買 = 管理費 → 修繕積立金 → 駐車場 → **仲介手数料(上限)**(戸建・土地は 駐車場 → 仲介手数料(上限)の2行)。**売買の仲介手数料は価格から計算した法定の上限額**(02 §3-3・J-094)なので、ラベルに「(上限)」を付け、値の下に最小・灰で「宅地建物取引業法の上限額(価格の3%+6万円+消費税)。実際の額は異なる場合があります」と添える。**計算で出した値は、上限であることと実額が異なりうることを必ず画面に書く**(書かずに出すと確定額に読める)。売買には入居時の目安合計に相当するものは作らない(頭金・諸費用・税金は 02 にデータが無く、目安を出せない)。家賃は右カラムの「毎月」(= 合計)に置くのでここには出さない(J-093)。
   見出しを置かない理由:J-090 でまとまりの見出しを h4 にしたが、**見出しと項目名が同じ列の同じ位置に並び、どちらが見出しか見分けが付かなかった**。4つのうち「更新時」と「入居時の目安合計」は見出しと項目が1対1で、項目数も7行程度なので順番で追える。
   **合計だけは上の細い横線と余白で区切って最後に置く**(他は条件、合計は計算結果で性質が違う)。金額は太字、範囲の注記(J-087)は値の下に置く。
   **ラベルは 7.5em の固定幅・値の欄は 32em を上限にして左寄せ**(1列で全幅に伸ばすとラベルと値が離れて読みにくい)。合計の行は**上線と余白だけで区切り、上パディングは他の行と同じ 8 にする**(`pt` を足すと行の中身が他の行より下にずれる)。J-061 の「左 = お金 / 右 = 住まいの条件と時期」は、右が2行しかなく 1280px で右半分が空いたため取りやめ、**向きは建物(売買は 土地・建物)へ、入居可能日(売買は引渡し)は契約・掲載へ移した**(02 §3-1 の共通フィールド = 建物の属性 / 02 §3-2・§3-3 の契約系、という分け方に合わせる)。売買の3つ目の区分は引渡しが入るので「掲載」→「**契約・掲載**」に改名する。**賃貸の左列は費用を時点順に4つのまとまりで出す(J-084)**:毎月(家賃 / 管理費・共益費 / 駐車場)→ 最初に必要(敷金 / 礼金 / **仲介手数料**)→ 更新時(更新料)→ 入居時の目安合計(太字の金額 + 最小・灰で「家賃・管理費・敷金・礼金・仲介手数料の合計。保証料・保険料・日割り家賃は含みません」。**含む項目だけでなく含まない項目まで書く**・J-087)。まとまりの見出しは 最小・灰、行の作り(ラベル 6.5em・下の細い横線・値は本文サイズ)は情報表の他の行と同じ。家賃の行を出すのは、注記が5項目の合計と書いている以上、内訳に家賃が無いと検算できないため(01 §3「初期費用は隠さない」)。合計が出せない物件はそのまとまりごと出さない。閉じている時の補足は「家賃・初期費用・駐車場など」。売買 = 管理費 / 修繕積立金 / 駐車場 // 向き / 引渡し(戸建・土地に無い項目は出さない。売買は 02 §3-3 に仲介手数料が無いので合計を出さない)。駐車場は月額が発生する項目なのでお金側に置く。向きを残すのは日当たりが重視条件の上位に入るため。階数は内見で見る情報なので詳細へ送る。
2 **詳細**:素の `<details>` / `<summary>` のアコーディオン(J-062)。確認と合わせて3つが同列に並ぶ。賃貸 = 「建物」「契約・掲載」、売買 = 「土地・建物」「掲載」。**どちらも初期状態は閉じる。JavaScript は使わない**(トップの検索フォームと同じ理由・J-056)。1つにまとめると開いた時に 11項目が一度に出て量が減らないため、見たい方だけ開ける形にする。中に小見出しは置かない(見出しと重複するため)。
   閉じていても中身が分かるよう、**見出しの右に小さな説明**(小・灰)を添える:入居前に確認すること = 「管理費・更新料・駐車場など」(売買は マンション「管理費・修繕積立金・駐車場など」/ 戸建「駐車場・向き・引渡しなど」/ 土地「駐車場・引渡しなど」)、建物 = 「所在地・築年月・構造など」、契約・掲載 = 「契約期間・保証人・取引態様など」、土地・建物 = 「所在地・築年月・土地権利など」(土地は「所在地・土地権利・用途地域など」)、掲載 = 「取引態様・物件番号・情報更新日など」。
   費用のまとまり(毎月 / 最初に必要 / 更新時 / 入居時の目安合計)は、**各まとまりの最終行の下線を消し、区切りは見出しの上の余白だけ**にする(J-088。線と余白が二重に見えるため)。
   2つは隙間を空けず、上下の細い横線で2行に見せる(1行 約50px)。開閉は §8 の 200ms・cubic-bezier(0.4, 0, 0.2, 1)、prefers-reduced-motion では動かさない。
**開閉する見出しと常時表示の見出しの区別(J-061)**:見出しの文字(H3・太字・墨)は同じにし、次の2点だけで区別する。
- 開閉する見出しは**左に開閉の印**(lucide の ChevronRight 20px・薄い灰。開くと 90 度回して下向き。200ms・§8 のイージング)。常時表示の見出しには印を付けない。
- 開閉する見出しは**行全体が hover で淡い青緑 `#E0F2F1`**(150ms・cursor pointer・J-035 と同じ規則)。押せる範囲は見出しから行の右端まで。
印は左の1つだけにする。右端に矢印を置くと、幅の広い画面で見出しと 1000px 以上離れ、矢印だけを押すものに見える(J-061)。

**畳んだ中身も HTML に出す**:`details` の中身はマークアップとして存在するので、構造化データとクロール可能 HTML の方針(制作計画 §7-8)に反しない。JS で後から差し込む形にはしない。
決め手の3項目に出した値(交通の1駅目・家賃・間取り・専有面積・町・初期費用 / 売買は町・価格・管理費+修繕の合計)は表から外す。2駅目と沿線は詳細情報の「建物」に残す。

**情報表の区分(J-054)**:区分はデータの種類ではなく読む人の関心順に置く。帯(J-047)の直下に「条件」の区分を1つ置き、その下に確認用の区分を続ける。
- 賃貸:A「入居の条件」(左 = 交通 / 間取り / 専有面積 / 階数 / 向き / 駐車場、右 = 家賃 / 管理費・共益費 / 初期費用 / 更新料 / 入居可能日。J-055 で入居可能日を右の末尾へ)→ B「建物と所在地」(所在地 / 築年月 / 構造)→ C「契約と掲載」(左 = 契約期間 / 保証人 / 取引態様、右 = 物件番号 / 情報更新日 / 次回更新予定日)
- 売買:A「購入の条件」(左 = 交通 / 間取り / 面積 / 階数 / 向き / 駐車場、右 = 価格 / 管理費 / 修繕積立金 / 引渡し。J-055 で引渡しを右の末尾へ)→ B「土地・建物の仕様」(所在地 / 築年月 / 構造 / 権利 / 用途地域 / 建ぺい率・容積率 / 接道)→ C「掲載情報」(取引態様 / 物件番号 / 情報更新日 / 次回更新予定日)
- 設備ブロックは A の中の最後(選ぶ条件なので確認用より上)。A は帯と同じ白い角丸カード(灰線・影なし・内側 16)に入れて先に読ませ、B・C はカードに入れず見出しを薄い文字色にする。A と B の間は 32。
- 項目は減らさない・折りたたまない(J-051 の「属性はできるだけ見えるように」を維持)。J-051 のリンクは区分が変わっても維持する。帯の5項目(J-047)は変えない。
- 沿線は独立した行を持たず、交通の値の下に小さい文字(小・薄)で添える(J-055。行は増やさない。沿線のリンクは維持)。
- 「なし」の値(管理費・共益費 / 更新料 / 駐車場 など)は太字。色は付けない(リンクの青緑と紛らわしくなるため)。保証人は値にかかわらず太字(J-055。有無そのものが判断に効く項目のため)。

**情報表の組み方(J-052 → J-090)**:ラベル列は **7.5em の固定幅**(J-052 の 6.5em = 104px は「管理費・共益費」の必要幅 91px に対して余白が 13px しかなく、環境差で折り返しうるため J-090 で拡幅した)、値はその右に詰める。設備は2列の表に収まらないので表の外に出し、表の下に全幅のブロック(H3「設備」)としてチップを横に流す。面積(専有・土地・建物)は「基本」から「建物」へ移し、基本 = 所在地 / 交通 / 沿線 / 間取り(左2・右2)、建物 = 専有面積 / 階数 / 向き / 築年月 / 構造 / 駐車場(左3・右3)にする。「契約・掲載」は左右で中身を分ける:左 = 契約(契約期間 / 入居可能日 / 保証人 / 取引態様)、右 = 掲載(物件番号 / 情報更新日 / 次回更新予定日)。左右に混ぜると「次回更新予定日」が契約の更新に読めるため。

**押せるものの見た目(J-052 → J-096 → J-115 で範囲を拡大)**:対象は **物件詳細・物件一覧・条件固定の一覧・入口ページ(エリア / 沿線・駅 / 特集)・説明ページ(§7・会社案内系)**。トップ・フォームは対象外のまま(J-096 時点)。J-058 の「同じ面に白い角丸カードを2列続けない・会社の説明は枠なし」も説明ページに効く(J-115)。押せるものは2種類に統一する。
1 **押せるチップ**(ポイントタグ・設備・種目):白地 + 青緑の細枠 + 青緑の文字(枠と文字は §2 のリンク色の段。新しい色は足さない)。ポイントタグの淡い塗りはやめる(設備と行き先が同じなので重みを揃える)。
2 **押せる文字**(沿線・間取り・所在地・交通。一覧側では 入口ページの町名・駅名・沿線名・特集名・「賃貸 ○件 / 売買 ○件」・左カラムの「他のエリアから探す」):青緑の文字・下線なし。hover で下線を出す。
一覧側でも既存の部品(チップ = 駅・クイック条件、チェック = エリア・間取り、× 付きの条件タグ)は変えない。これらは「選ぶ」操作であり「移動する」リンクではないため(J-096)。
どちらも hover / active で背景を淡い青緑 `#E0F2F1`・150ms・cubic-bezier(0.4, 0, 0.2, 1)・cursor pointer(J-035 と同じ規則)。
押せないもの(向き・築年月・構造・駐車場・保証人・取引態様・契約期間・入居可能日・物件番号・情報更新日・次回更新予定日・面積・金額)は本文色の黒のまま。
**塗り = 状態、線 = 分類かつリンク**:新着・値下げなどの状態バッジは塗りのまま変えない。
**トップの面の使い分け(J-058)**:同じ面に白い角丸カードを2列続けない。会社の説明(強み3点)は枠も背景も持たせず アイコン(lucide 24px・青緑)+ 見出し H3 + 本文 の3列、リンクの入口(初めての方へ / 売却 / オーナー様の3枚)はカード(白・角丸・灰線、hover で淡い青緑)にする。役割が違うものを同じ形にしない。
**一覧の行は列を揃える(J-058)**:日付+タグ+タイトルのような行は、日付とタグに固定幅を与えてタイトルの左端を揃える(日付 7.5em・カテゴリータグ 8.5em。最長の「部屋探しのコツ」が折り返さない幅)。文字数で開始位置が動くようにしない。

**アイコンは隣の文字の大きさに合わせる(J-071)**:行の先頭に置くアイコンは、隣の文字に対して**同じくらいの高さ**に見える大きさにする。本文サイズ(15 / 16px)の行は 16px。線の太さの分だけ大きく見えるので、大きい文字に付ける場合は**文字の 7〜8 割**に落とす(数値をそのまま合わせない)。揃えは行の文字の大きさで変える(J-074):**大きい文字はベースライン**(`items-baseline`。アイコンの下端を文字のベースラインに載せる)、**本文サイズの行は中央**(`items-center`)。本文サイズでベースラインに載せるとアイコンが文字より 1〜1.5px 上に見えるため。色は青緑(accent)。文字サイズが幅で変わる行は、アイコンも一緒に変える。
**ただし詳細ページの右カラムの価格(家賃 / 価格)にはアイコンを付けない(J-072)**:大きさを合わせてもアイコンが価格より目立つため。価格は文字だけで、左端は物件名・住所・費用の内訳・要約と揃える(アイコンのある2行だけが 20 内側に入る)。

**押せるものはカーソルを変える(J-067)**:ボタン・サムネイル・矢印・閉じる(×)は `cursor: pointer`。拡大を開くメイン画像だけ `cursor: zoom-in`(押した先が拡大だと分かるため)。押せるものの上でテキスト選択が走らないよう `select-none` も併せて付ける(F-008)。

**ギャラリーのサムネイル(J-066)**:選択中は**青緑の枠 2px**。選択していないサムネイルも枠は 2px のままにし、色だけ変える(ページ = 灰線、モーダル = 白の 40%)。太さを変えないのは、選び直したときに画像の大きさが動かないようにするため。
ホバー中のサムネイルは薄くする(150ms・cubic-bezier(0.4, 0, 0.2, 1)・cursor pointer・prefers-reduced-motion では無効)。**選択中のサムネイルはホバーしても変えない**(押しても表示が変わらないため)。
地色で見え方が変わるので、**ページ(白地)は不透明度 60%**、**モーダル(墨95%の暗地)は明度 +50%** で薄くする(暗地で不透明度を下げると地に沈んで「濃くなった」ように見えるため)。枠の色はホバーでページが青緑、モーダルが白。

**最近見た物件のカルーセル(J-064 → J-065)**:横スクロールバーは出さない。md(768)以上は見出しの右に矢印(前 / 次・36px・灰枠)を置き、**1件ずつ** transform で送る(200ms・§8 のイージング。J-065。J-064 は1画面ずつだった)。1画面の枚数は 768〜1023 が2枚、1024 以上が4枚。スマホ(〜767)は scroll-snap の横スワイプで、カード幅は画面の 85%(次の1枚が見えて横に続くと分かる)。**端はループする**(J-065。末尾の次は先頭、先頭の前は末尾。向きは変えないので巻き戻して見えない)。**矢印に disabled は入れない**(J-049 で端の disabled がフォーカスを奪う不具合が出た経緯があり、ループなら構造的に起きない)。仕組みは「1画面の枚数+1枚」を並べて1枚分ずらし、並びを回して位置を戻す(カードの複製は持たない)。件数が1画面の枚数以下なら矢印を出さない。幅が変わっても左端の物件は保つ。カードは J-046 のまま。

**共有導線(J-086 → J-089 → J-091)**:置き場所は幅で分ける(J-091)。**PC(lg = 1024 以上)は画面の右下に追従**(白・角丸 6・灰線・影なし = §5 のカード、内側 16 / 8、右下から 16、z-30 = 固定CTA と同じ段)。**〜1023 は追従させず、ページ下部の CTA の中、注意書きの1行上**に置く(右カラムは写真と高さを揃えているので伸ばさない・J-084)。中身は **URL をコピー / LINE で送る の2つだけ**。見た目は **J-052 の「押せる文字」**(青緑の文字・下線なし・hover で下線と淡い青緑の背景・小 13px)にし、頭に lucide 16px のアイコンを添える。**副ボタン(枠線・高さ 44)にはしない**(J-089。主CTA と同じ高さ・同じ枠線だと、格下の用件に主CTA と同じ重みが付く)。見出し「この物件を共有」は置かない。**コピーの結果は文言で返す**(「URL をコピー」→「コピーしました」・2秒で戻す)。押しても何も起きない見た目にしないため、**JS が動かない環境では URL コピーのボタン自体を出さない**(LINE は素のリンクなので出す)。成約済みでも出す(共有の必要は残る)。幅の境界は**固定CTA(FixedCta)と同じ lg** にし、スマホで浮くものを2つにしない。追従は本文の上に出るので、地図のように全幅の要素とは重なる(z-30 なのでヘッダー z-40・スキップリンク z-50 より下、地図は .leaflet-container 側で閉じてあるので前後は崩れない・F-009)。

**押せないタグは別系統(J-057)**:お知らせのカテゴリー(お知らせ / 部屋探しのコツ / 地域情報)は白地 + 灰の細枠 + 灰の文字の**押せないタグ**にする。物件の属性タグ(青緑の枠・文字でリンク)と同じ見た目にすると押せると誤解されるため、色で系統を分ける。絞り込みに繋がるタグだけが青緑。
**日付の表記(J-057)**:サイト全体で「2026年9月8日」に揃える(月日の先頭の0は落とす)。整形は lib/format.ts の dateLabel に寄せ、ページごとに別の書き方をしない。日付でない値(「即入居可」「相談」)はそのまま出す。

**詳細ページの部品(J-038)**:ギャラリーはメイン 3:2 + サムネイル高 56(スマホ)/ 64(PC)、間取り図を末尾に。写真0枚(60件中3件)はメインに間取り図を出さず、薄灰の面に「写真準備中」+ 小さく「間取り図を見る」を出す。押すとモーダルが開き、間取り図1枚だけを出す(矢印・枚数表示・サムネイル行はなし。J-049。J-038 のバッジは文言が重なるのでやめた)。ギャラリーはモーダル+スライダー(J-048):メイン画像を押すと全画面のモーダルが開き、拡大画像・左右矢印(lucide 24px)・「3 / 6」の枚数・サムネイル行(現在の1枚は青緑枠)・右上の × を出す。← → キー / Esc / 背景と余白のクリック / スマホの横スワイプで操作する。PC の送りは端でも巡回する(J-049。スマホのスワイプは端で止まる)。スマホ(〜767)はメイン画像自体も横スワイプでき、タップでモーダルも開く。開いている間は背面をスクロールさせない。ライブラリは足さず <dialog> と CSS の scroll-snap で作る。地図は高さ 256(スマホ)/ 320(PC)・ズーム 15・ホイール無効・墨の丸マーカー。CTA は 内見予約(売買は「見学を予約する」)と「問い合わせる」の2つ。**どちらの箱も2列**:右カラムは 1024 以上(右カラムが独立する幅)で左=内見予約 / 右=問い合わせ(J-075)、ページ下部は 640 以上で同じ並び(J-064)。それぞれの下の幅では縦に積む。成約済みは内見予約を出さないので残る1つが全幅になる(J-038 判断1)。問い合わせの文言は**「問い合わせる」の1語**に統一する(J-075。1024〜1080px の右カラムでは「この物件を問い合わせる」が2行になり、高さ 44 のボタンからはみ出す。物件詳細ページにいるので「この物件を」は自明)。予約側は「内見を予約する」「見学を予約する」のまま(いちばん狭い 182px のボタンでも1行に収まる)。上下2箇所で同じ文言にし、幅で文言を変えない。問い合わせの文言は1行にする。電話はヘッダー右上とスマホの固定 CTA に置き、詳細ページ本文には置かない。要約と CTA の間は 16(J-050。電話を外した分 24 から詰め、右カラムの下端をギャラリーの下端に合わせる)。状態バッジ(新着・値下げ)と同じ行に種目を出す:状態は塗りのバッジ、種目は塗りのない枠線だけのリンク(最小・太字・薄い文字色)で形を分ける。種目はその種目で絞った一覧へのリンク(J-051 の仕組み)。成約済みは内見予約を出さない(固定 CTA も)。**右カラムに何を置くかの基準(J-092)**:この場所は J-050 → J-070 → J-079 → J-084 と4回組み替えている。並び順だけを決めても同じことが起きるので、**入れる / 入れないの判定基準**をここに置く。

右カラムに置くのは、**次の3つをすべて満たす項目だけ**。
1. **一覧の絞り込み条件にあるか、一覧のカードに出ている項目である**(= 探す段階で使われた情報)
2. **物件を候補から外す / 残すの判断に直接使う**(= 見比べる情報。読んで確かめる情報ではない)
3. **内訳や注記を伴わない。値そのものが完結している**
   ※ **高さが可変であることは除外の理由にしない**(設備チップのように個数で高さが変わる項目も、1〜3 を満たすなら置く)

**項目名が同じでも意味が異なる場合は、文言を変えて区別する。** 例:右カラムの設備チップ「駐車場」(その条件で絞った一覧へのリンク)と、物件データの駐車場の行(その物件の駐車場の状況)が同じ語で並んでいた。**適用(09/15):物件データ側を「駐車場の状況」に変えた**(02 §3-1 の `parking` は「なし / 空きあり(月額) / 近隣」の3値で**敷地外も含む**ため、「敷地内駐車場」では値と合わない)。設備チップ側は一覧の検索条件と揃える必要があるので変えない。
**同じ項目を右カラムと物件データの両方に出さない。** 右カラムに置いた項目は物件データから外す(逆も同じ)。二重に強調すると、どちらが判断の場所か分からなくなる(J-070 の出発点と同じ問題)。

**毎月かかる費用は価格の直下に1行で置く**(J-059 の「住宅は毎月の支払いで判断される」を引き継ぐ)。呼び方は種別で変える。
- 賃貸 …… 「毎月」= 家賃 + 管理費・共益費
- 売買マンション …… 「毎月の維持費」= 管理費 + 修繕積立金。**「毎月の支払い」とは呼ばない**(ローンが含まれると誤解されるため。ローンの額は 02 にデータが無く、金利や頭金を仮定すると架空の数字を作ることになる)
- 戸建・土地 …… **行ごと出さない**(「—」も出さない。欠損ではなく、その種別に毎月の維持費が無いという性質のため)
- **毎月の費用は値がある場合のみ出す。0円や空の行は作らない**(J-093 の残件)。賃貸で管理費・共益費が無い物件は、合計が家賃と同額になり、大きな価格表記のすぐ下に同じ金額が別の書式で並ぶだけで情報が増えないため出さない(実測:賃貸40件のうち管理費ありは20件)

**条件1は一覧の実装に依存する。一覧の仕様(絞り込み条件・カードの項目)が変わったら、右カラムの構成も見直す。**

右カラムの並び(J-070 → J-093 で基準どおりに整理):**状態バッジ+種目 → 物件名(H1)→ 駅徒歩+町名 → 価格 → 毎月(売買マンションは毎月の維持費)→ 値下げ前(あれば)→ スペック(間取り / 面積 / 階 / 築年)→ 設備チップ → CTA**。要約4行(築年 / 向き / 入居可能日 / 2駅目)は J-093 で廃止した:向き・入居可能日・2駅目は基準の条件2(候補を外す / 残すの判断に直接使う)を満たさず、向き・入居可能日は物件データにも同じ行があって二重だった(J-088 で下へ移した時に右カラムを見落としていた)。2駅目は物件データ「建物」の交通の欄に2駅とも入っているので右カラム側を消すだけでよい。築年は条件を満たすのでスペックの行に「/ 築18年」として残す。以下は各行の作り。駅徒歩+町名を1行に(本文・太字・左に lucide TrainFront 16px 青緑。町名は区切り「/」の後に 小・薄・細字で添える。番地は出さない。完全な住所は詳細情報の所在地に残す・J-071 → J-073)→ **家賃 / 価格**(価格の文字。アイコンは付けない・J-072)→ **費用の内訳は右カラムに置かない(J-084)**:賃貸の 最初に必要 / 入居時の目安合計 は物件データの「入居前に確認すること」へ置く(下の「物件データ」の項)。理由は2つ:(1) **中身が増えて上部の CTA がファーストビューから出たため**(2) **上の基準の3**(内訳と合計は注記を伴い、値だけで完結しない)。
**高さの扱い(J-093 の実測)**:右カラムの**箱の高さはグリッドの行が決めており、ギャラリーと同じ高さに引き伸ばされる**(1280px で箱 550・下端 729 = ギャラリーの下端、中身の下端は 541 で箱の下端まで 187px 空く)。**箱は中身が増えても伸びない。伸びるのは中身**で、それが下にある CTA を押し下げる(J-080 で費用を右カラムに置いた時は、中身が伸びて主CTA が 800px の画面の外に出た)。**J-084 以来「ギャラリーとの差0」だったのは、中身を合わせた結果ではなく最初から箱が固定だったため**。1023px 以下は縦積み(block)になるので箱 = 中身。
したがって**高さを写真と揃えることは基準にしない**(合わせにいくと中身の選び方が高さに従属する)。見るのは箱の下端ではなく、**主CTA がファーストビューに入っているか**。→ 値下げ前(あれば)→ **スペック**(本文・太字・左に LayoutGrid 16px 青緑。間取り / 面積 / 階。土地は「土地 77㎡」)→ **設備のチップ**(J-052 の押せるチップ。見出しは置かずチップだけ。最多 10個で2段・72px。J-074 で物件概要から移した)→ 要約4行 → CTA。駅徒歩を住所より先に置くのは、探す段階で効くのが駅徒歩で、番地は後から確認する情報だから。物件名にアイコンは付けない。スペックの下の区切り線は置かず、余白 24 で要約と分ける(要約の罫線と役割が混ざるため)。
右カラムの要約(J-039 → J-068):価格の下・CTA の上に 築年 / 向き / 入居可能日(売買は引渡し)/ 最寄2駅目(13px)。PC(lg 以上)は**縦1列**で、ラベルは 6.5em の固定幅・値はその右(情報表と同じ規則・J-052)。上から拾い読みできるようにするため、左右の視線移動を作らない。各行の下に細い横線(`border-line` 1px・情報表と同じ)を引き、**最終行の下にも引く**(4項目なら4本)。情報表は最終行の下に線を引かないが、要約はこの下に CTA のボタンが続くため、最後の1本で情報の切れ目を示す(J-069)。行の高さは情報表と同じ上下 8 にし、行間(gap)は 0 にする(線と余白が二重にならないように)。文字の太さはラベル・値とも変えない。スマホ・タブレット(〜1023)は2列×2行のままで**線は引かない**(2列に線を引くと横に2本並んで表に見えるため)。「この物件について」(J-039):本文の上に「ポイント」チップ最大3。優先順は 特集(02 §2 の名前・順)> 駅徒歩5分以内・10分以内 > 新築・築5年以内 > 設備(02 §2 順、エアコン除外)。特集「駅徒歩5分」「新築・築浅」「ペット可」があれば同じ意味の段は出さない。値下げ・種目・間取り・費用系・2駅利用可は出さない。淡い青緑の面+青緑枠。各タグは同じ条件の一覧へのリンク〔collection / walk_max / built_max / feature・売買は type=sale〕、hover は J-035 と同じ(J-040)、属性リンク(J-051):情報表の 所在地(区・町)・交通(駅名)・沿線・間取り・設備チップも同じ仕組みで一覧へ飛ばす。URL は lib/links.ts の listHref(クエリ名は lib/search.ts と同じ・売買のみ type=sale)。リンクにするのは一覧の左カラム(J-034)に絞り込みがある項目だけで、向き・入居可能日・階・面積・築年・金額はリンクにしない。区の絞り込みは一覧に無いので、区リンクはその区の町を OR で並べる。0件になるリンクもリンクのままにする、本文は担当者カードの中に入れて1枚にする(J-053。見出しとポイントタグは外に残す)。カードは全幅・白地・灰枠で、PC(640 以上)は左に顔写真(プレースホルダー・3:4・幅 240)、右に「担当 氏名(架空)」+ 役職・資格 + 細い横線 + 紹介文。右のテキストに最大幅は付けない。**スマホ(〜639)は上下に積み、写真はカードの幅いっぱい(3:4 のまま・J-078)**。横に並んでいる時の幅(240)を縦積みでも使うと、広い余白の左端に小さい画像が取り残されるため。テキストは左揃えのまま変えない。顔写真は物件写真と同じ作りの SVG プレースホルダー(灰地 `#6C737B` + 白 35% のシルエット)で、実写真は使わない。**シルエットは頭と肩・胴をつないだ1つの人型にする**(円と半円を離して置くと人に見えない・J-077)。**画像内の文字は「架空・プレースホルダー」の1行だけ**にし、氏名・役職は入れない(右のテキストに同じものが出るため)。画像単体で見られた時に架空だと分かる状態は、この1行で保つ(制作計画 §7-9)。

1 **幅と列**:フォーム本体は最大幅 760(入力欄と本文の読み幅・J-103。J-052 の 760 は J-053 で撤回されているので根拠にしない)・1列。入力欄は tab の順に読ませるので「順番に意味がある情報」に当たり、2列に流さない。例外は**1つの項目を2つの操作子で表すもの**(希望日時 = 日付 + 時間帯)だけで、これは横に並べる(スマホも)。項目間は 16、まとまりの間は 32。まとまり(例:対象物件 / ご希望 / 連絡先)の見出しは H3、その下に区切り線は引かない(見出しと線が二重になる・J-088 と同じ理由)。

2 **操作子**(ネイティブ要素を使い、ライブラリは足さない):
- セレクト:入力欄と同じ高さ 46・枠・focus。右端に lucide ChevronDown 20px・灰。絞り込み欄のセレクト(40 / 32)とは別で、本文中のフォームは 46 に揃える。

## 10. 手直しの型(初案は一発で決まらない前提)

1ページにつき「初案 → 判断 → 修正」が1〜3往復出る。往復の回数そのものが章2・章6の実測なので、減らすことより**記録すること**を目標にする。

**手直しは3種類。直す前にどれかを判定する。**

| 種類 | 例 | やること | 記録 |
|---|---|---|---|
| **A. 基準違反** | この基準に無い色・スケール外の余白・純黒・2書体目 | 基準を守るよう直させる。基準は変えない | AI の誤り → F-ID(気づいた手段を書く) |
| **B. 基準の不備** | 基準どおりに作ったらスマホで詰まる・読めない | **この基準を先に直し、版を上げてから**ページを直す。他ページにも効く | J-ID(条件追加)。基準の変更履歴を末尾に残す |
| **C. ページ固有の調整** | CTA の位置・見出しの文言・このページだけの並び | ページだけ直す | J-ID(却下 / 条件追加)か「そのまま採用」1行 |

B と C の区別が肝。C だと思って直したものが B(他ページでも出る)だと、後で全ページを触る。**迷ったら B 扱いで基準に書く。**

**1ページの流れ**
1. `/build-page` で初案 → before スクショ(スマホ・PC)を `docs/screenshots/` に
2. 判断ポイントと気になる点を A / B / C に分けて番号で返す
3. `/log-judgment` で記録 → 直させる → after スクショ
4. 2往復で収まらない項目は「AI に頼んでも直らない箇所」(章6)として記録し、手で直すか、置いて先に進む
5. コミット `feat: add <page> [J-NNN]`

**往復を増やさないために**
- 1往復目は構成と情報の順序だけ見る。色や 1px は2往復目
- 細かい調整を1つずつ J-ID にしない。1ページ 1〜2 件の J-ID に条件を箇条書きでまとめる
- 実装順 0(土台)で、ヘッダー・フッター・カードを実データで**わざと崩す**(長い物件名・写真0枚・成約済み・6枚)。ここで B を潰すと、以降は C だけになる
- 実装順 0〜3 は往復が多くて正常(基準の不備が出る時期)。4 以降は減る
