# 02 物件データ設計

**作成日:2026-09-05**
**方針:構造は本番と同じ、値はダミー。**(§1・§2ステータス・§6 WP経由・写真プレースホルダー・意図的欠損 は 2026-09-05 承認済み → J-014〜018) 検索・絞り込み・地図・SSGの実装と記録が本番同等に取れる構造にし、物件名・家賃・住所・写真はすべて架空にする。

---

## 1. 投稿タイプ

**`property` 1つ。賃貸/売買は種別タクソノミーで分ける。**

| 案 | 採否 | 理由 |
|---|---|---|
| `property` 1つ+種別タクソノミー | **採用** | 一覧・検索・地図が賃貸/売買を横断できる。トップの検索フォームがタブ切替で済む。コードの重複が出ない |
| `rental` / `sale` の2つ | 不採用 | 一覧の横断で2回取得が要る。フィールドの大半が共通なので分ける利点が薄い |

賃貸専用・売買専用のフィールドは、種別に応じて表示/非表示にする(§4)。

---

## 2. タクソノミー(検索に使う項目)

検索・絞り込みの条件になるものはタクソノミーに置く。理由:URL同期(`?area=aoto&line=keisei`)と静的生成(`/area/[slug]`)がスラッグで揃う。

| タクソノミー | slug | 階層 | 項目(ダミー・会社設定に整合) | 複数付与 |
|---|---|---|---|---|
| 種別 | `property_type` | なし | 賃貸 / 売買 | 単一 |
| 物件種目 | `property_kind` | なし | 賃貸:マンション / アパート / 戸建賃貸 / 売買:マンション / 戸建 / 土地 | 単一 |
| エリア | `area` | あり(区→町) | 葛飾区(青戸・立石・お花茶屋・亀有・新小岩・金町・堀切)/ 江戸川区(小岩・平井)/ 足立区(綾瀬・北千住)/ 墨田区(押上・曳舟) | 単一(町) |
| 沿線 | `line` | なし | 京成本線 / 京成押上線 / JR常磐線 / JR総武線 / 都営新宿線 / 東武スカイツリーライン | 複数可 |
| 駅 | `station` | なし(沿線とはメタで紐付け) | 青砥 / 京成立石 / お花茶屋 / 亀有 / 新小岩 / 金町 / 堀切菖蒲園 / 京成小岩 / 平井 / 綾瀬 / 北千住 / 押上 / 曳舟 | 複数可(最寄2駅まで) |
| 設備 | `feature_tag` | なし | ペット可 / オートロック / 駐車場 / 宅配ボックス / バス・トイレ別 / 独立洗面 / 追い焚き / エアコン / 南向き / 角部屋 / 2階以上 / 敷金礼金ゼロ / 即入居可 / 楽器可 / 事務所可 | 複数可 |
| 特集 | `collection` | なし | 都心まで30分以内 / 敷礼ゼロ / ペット可 / 戸建賃貸 / 駅徒歩5分 / 新築・築浅 | 複数可 |
| ステータス | `status` | なし | 公開中 / 新着 / 値下げ / 商談中 / 成約済み | 単一 |

**判断ポイント(記録)**
- 「駅」を沿線の子にしない理由:1駅が複数沿線に属する(押上=京成押上線+都営浅草線等)。フラットにして駅側に沿線IDをメタで持たせる
- 「設備」と「特集」を分ける理由:設備は物件の属性、特集は編集判断。特集は設備の組み合わせで自動付与もできるが、**手動付与にする**(「都心まで30分以内」は設備からは導けない)
- 「ステータス」に「新着」を入れるか:公開日から14日以内を自動で新着にする方が実務的。**ステータスは「公開中/商談中/成約済み」の3値にし、新着・値下げはフィールドから導出**する(§3)。表の「新着/値下げ」は表示バッジであり、タクソノミーではない → 決定:3値

## 3. カスタムフィールド(表示に使う項目)

ACF無料版で構成。リピーターは使わない(Nordic Works と同じ制約)。

### 3-1. 共通

| フィールド | key | 型 | 備考 |
|---|---|---|---|
| 物件番号 | `property_no` | text | `HR-R-0001`(社略・種別・連番。賃貸=R / 売買=S)。URLの `[id]` に使う |
| 所在地(表示用) | `address` | text | 「東京都葛飾区青戸0-0-0」。番地は必ず 0-0-0 |
| 緯度 / 経度 | `lat` / `lng` | number | 町名の中心±0.004度の乱数。実在建物に一致させない |
| 最寄駅までの徒歩分 | `walk_minutes` | number(1〜20) | 最寄1駅目。2駅目は `walk_minutes_2` |
| 最寄1駅目 | `primary_station` | text(駅 slug) | タクソノミー `station` は名前順で返るため、1駅目をここで持つ。REST の `hr_terms.station` と `index.json` の `stations[0]` はこの駅(2026-09-08 追記・J-033・F-005) |
| 間取り | `layout` | select | 1R / 1K / 1DK / 1LDK / 2K / 2DK / 2LDK / 3DK / 3LDK / 4LDK |

| 向き | `direction` | select | 南 / 東 / 西 / 北 / 南東 / 南西 |

| 担当者 | `staff` | select | スタッフ8名(架空氏名) |

### 3-3. 売買専用

| フィールド | key | 型 | 備考 |
|---|---|---|---|
| 価格(万円) | `price` | number | |
| 土地面積(㎡) | `land_sqm` | number | 戸建・土地 |
| 建物面積(㎡) | `building_sqm` | number | 戸建 |
| 管理費 / 修繕積立金 | `mgmt_fee` / `repair_fund` | number | マンション |
| 土地権利 | `land_rights` | select | 所有権 / 借地権 |
| 用途地域 | `zoning` | select | 第一種住居 / 近隣商業 / 準工業 等 |
| 建ぺい率 / 容積率 | `bcr` / `far` | number | 土地・戸建 |
| 接道 | `road_access` | text | |
| 引渡し | `handover` | text | 「相談」「即時」 |
| 前回価格 | `price_previous` | number | 「値下げ」判定 |
| 学区(小・中) | `school_district` | text | **会社設定で「入れる」に決定した場合のみ**(§8) |

**判断ポイント(記録)**
- 「新着」「値下げ」をタクソノミーではなくフィールドから導出する理由:手動付与は更新漏れが起きる。公開日と前回価格から自動判定する方が実務に近く、AIの初案(ステータスに全部入れる)との差になる
- `images` を textarea の区切り文字で持つ:ACF無料版にギャラリーがないため。Nordic Works の「リピーター代替」と同じ判断を再利用
- **写真0枚の物件を意図的に含める**:設計図の判断ポイント「写真がない物件の表示」を必ず通すため

## 4. 種別による表示制御

| 場所 | 賃貸 | 売買 |
|---|---|---|
| 一覧カードの主数字 | 家賃(+管理費) | 価格(万円) |
| 詳細の基本情報表 | 3-1 + 3-2 | 3-1 + 3-3 |
| 検索条件 | 家賃・間取り・駅徒歩・築年・面積・設備 | 価格帯・種目・面積・築年・**駅徒歩・設備**(2026-09-11 追加・J-043。設備は売買に該当のあるものだけ。学区は入れない・§8-3) |
| CTA | 内見予約 | 資料請求・内見予約 |

WP側では全フィールドを1つのフィールドグループに置き、ACFの条件判定(種別タクソノミーの値)で管理画面の表示を切り替える。

## 5. JSONの分割単位(export-wp-data.mjs の出力)

```
web/data/
├ properties/
│  ├ index.json          全件の一覧用サブセット(カード表示に必要な項目のみ+全タクソノミー)
│  └ HR-R-0001.json      1物件1ファイル(詳細ページ用・全フィールド)
├ taxonomies/
│  ├ area.json  line.json  station.json  feature_tag.json  collection.json  status.json
└ meta.json              取得日時・件数・Localのバージョン
```

| 案 | 採否 | 理由 |
|---|---|---|
| 1物件1ファイル+index | **採用** | 物件を1件追加した時の差分が1ファイルに収まり、Gitの履歴で追える。詳細ページのSSGは該当1ファイルだけ読む |
| 1ファイルに全件 | 不採用 | 60件で数百KBになり、差分が読めない |

`index.json` は一覧・検索・地図が読む。`walk_minutes` / `rent` / `price` / `area_sqm` / `built_ym` / 緯度経度 / 全タクソノミー / `images[0]` / バッジ判定用の日付を含む。

## 6. シードスクリプトの仕様(web/scripts/seed/)

| 項目 | 仕様 |
|---|---|
| 件数 | 賃貸40件・売買20件(合計60件) |
| 種目の配分 | 賃貸:マンション20 / アパート15 / 戸建賃貸5。売買:マンション8 / 戸建8 / 土地4 |
| エリアの配分 | 葛飾区30件・江戸川区12件・足立区10件・墨田区8件(本店エリアに寄せる) |
| 家賃(賃貸) | 間取りごとの範囲:1R/1K 5.5〜8.5万 / 1DK/1LDK 7〜12万 / 2K〜2LDK 9〜16万 / 3DK以上 12〜22万。駅徒歩と築年で±10%補正 |
| 価格(売買) | マンション 2,500〜6,500万 / 戸建 3,000〜7,000万 / 土地 2,000〜5,000万 |
| 面積 | 間取りと相関:1R/1K 18〜30㎡ / 1DK/1LDK 28〜45㎡ / 2K〜2LDK 40〜65㎡ / 3DK以上 60〜95㎡ |
| 築年 | 1975〜2026 に分布。**築浅が偏らないよう**、1990年代・2000年代を厚くする |
| 駅徒歩 | 1〜20分。5分以内を全体の25%(特集「駅徒歩5分」が空にならないよう) |
| 設備 | 築年と相関(2010年以降はオートロック・宅配ボックスの確率を上げる)。ペット可は全体の15% |
| ステータス | 公開中 80% / 商談中 12% / 成約済み 8%(掲載終了物件の扱いを必ず通すため) |
| 新着 | 公開日を直近60日に散らし、14日以内が10件前後になるようにする |
| 値下げ | 賃貸5件・売買3件に前回価格を設定 |
| 写真 | プレースホルダー(単色背景+物件番号+種目名のSVG→PNG)。枚数は0〜6枚。**0枚を3件**含める |
| 間取り図 | 間取りごとの汎用図形(SVG)10種を使い回す |
| 物件名 | `{町名}{汎用語}{番号}`。汎用語:ハイツ / コーポ / レジデンス / メゾン / テラス / ハウス。例「青戸ハイツ0-3」。**実在物件名との衝突確認は不要**(番号に0-を含める書式で実在名と一致しない) |
| 住所 | 「東京都{区}{町}0-0-0」固定書式 |
| 緯度経度 | 町名の代表座標(§8で一覧を作る)±0.004度の乱数 |
| 担当者コメント | 冒頭(立地)・中間(設備・間取り)・末尾(呼びかけ)の3部を各4パターンから組み合わせ(64通り) |
| 出力先 | WordPress REST(Local)へ投入する PHP スクリプト(`app/.../scripts/seed-properties.php`)。JSONは WP 経由で `export-wp-data.mjs` が書き出す(WP を経由しない直接生成はしない:実案件と同じ経路を通すため) |

**判断ポイント(記録)**
- **乱数に相関を持たせる**(間取り×面積、築年×設備、駅徒歩×家賃)。AIの初案は独立乱数を出しがちで、「1Rで90㎡・築2年でオートロックなし」のような物件ができる。ここが「ダミーでも業種理解が出る」箇所
- **分布を意図的に作る**(0件・成約済み・写真なし・値下げ)。検索の端の挙動を試すため
- **WPを経由する**。直接JSONを書けば速いが、実案件で使う経路(管理画面→REST→JSON)を通さないと記録にならない

## 7. 型定義(web/src/types/property.ts の骨子)

```ts
export type PropertyType = 'rental' | 'sale'
export type PropertyKind = 'mansion' | 'apartment' | 'house_rental' | 'house' | 'land'
export type Status = 'open' | 'negotiating' | 'sold'

export interface PropertySummary {   // index.json の1要素
  no: string; type: PropertyType; kind: PropertyKind; status: Status
  title: string; area: string; stations: { slug: string; walk: number }[]  // [0] = primary_station の駅(walk_minutes)、[1] = 2駅目(walk_minutes_2)
  lines: string[]; features: string[]; collections: string[]
  rent?: number; price?: number; layout: string; areaSqm: number; builtYm: string
  lat: number; lng: number; thumb: string | null
  publishedOn: string; rentPrevious?: number; pricePrevious?: number
}
export interface PropertyDetail extends PropertySummary { /* 3-1〜3-3 の全項目 */ }
```

バッジ判定(新着・値下げ)は `lib/` の純関数で行い、型には持たせない。
