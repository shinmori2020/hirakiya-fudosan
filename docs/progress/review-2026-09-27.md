## 反省点(今後の参考)

### 1. FV で 09/14 と同じ「往復」が起きた(最も大きい点)

| 対象 | 往復 |
|---|---|
| 高さ | J-132「画面の高さに合わせる」→ J-140 で撤回 → J-153 で再び画面の高さへ |
| 左右2列 | J-134・J-135 → J-151 で撤回 |
| 新着の小カード | J-147 → 2日後の J-149 で撤回 |
| タブ4つ(売る・貸す) | J-151 → 翌日の J-152 で一部撤回 |
| 副ボタン「初めての方へ」 | J-135 → J-148 で撤回 |

CLAUDE.md「同じ場所を2回目に触る時は、基準があるか確認する」が FV には当てはめられていなかった。FV の基準(必要なパーツ5つ)が書かれたのは J-151 の時で、それまでは「地味」「窮屈」という感想が起点だった。感想が起点だと、足して窮屈になり、減らして地味になる往復が起きる。
→ **今後**:「地味」「窮屈」と感じた時は、直す前に「FV で最初に見せるもの・置かないもの・画面の下端に入れるもの」を 03 に書き、案をその条件で判定する。

### 2. 1つの判断で2つを同時に変えると、結果の原因が見えにくい

J-153 は「FV を高くする」と「膜を薄くする」を同時に行った。高さを変えたことでキャッチが写真の明るい所に下がり、コントラストを保つために**文字のある左側の膜は 55〜70% → 62〜74% に濃くなった**。「暗さを緩和したい」という目的に対して、文字の周りは逆の結果になった(報告はしたが、判断の記録の上では目立たない)。
→ **今後**:見た目の変数は1つの判断に1つ。やむを得ず2つ変える時は、それぞれの影響を分けて測る。

### 3. 「悪くなった点」を読んだうえで採った案が、翌日に戻った

J-151 の試作2では「JS 無しで切り替えられない」「スマホで帯の高さが変わる」を報告し、AI は売る・貸すを押せる文字にする初案(試作3)も出した。見た目で試作2 を採り、翌日の J-152 で「フォームの一貫性がない」として外した。CLAUDE.md「報告の末尾を読む」と同じ型。
→ **今後**:試作の報告の「悪くなった点」は、採るかどうかを決める時に1行ずつ「受け入れる / 直す」を付けてから決める。

### 4. 「判断の出所」が後からまとめて埋められている

09/27 時点で J-148〜J-153 の6件が空欄。過去には J-109〜J-145 の多くが「AI の説明文をそのまま使う」指示で一括記入された。出所が AI の文になると、「人が判断した理由」という記録の一番の価値が弱まる。
→ **今後**:判断した日のうちに、一言でも自分の言葉で書く。

### 5. 別のチャットから届く指示が、実物と食い違うことがある

例:03 に無い「見えない間取り欄」を外す指示(J-151)/「残っていること」に無い項目(スクロール矢印の行き先)への追記の指示(J-151)/ J-152・J-153 の日付のずれ。どれも作業中に気づけたが、指示を作る側が実物を見ていないと起きる。
→ **今後**:大きな指示の前は、読むだけの洗い出しを先に頼む(09/27 の /sell・/owner のように)。日付は「コミット日時」と「チャットの日付」のどちらを使うかを決めておく。

### 6. 記録の置き場所の見直しが遅れている

スクショ(F-012)と同じ型で、記録シートは 2000行を超えた。撤回が起きると関係するブロックに追記が要る(J-151 では6箇所)。作業が増えるほど、記録を直す手間が大きくなる。
→ **今後**:置き場所の単位は「探す単位」で決め、想定を超えた時点で見直す(F-012 の学びをスクショ以外にも当てる)。

## まとめ

記録の仕組みと測り方はよくできていて、続いている。一方で、**FV のように好みで決まる場所では、基準が無いまま感想から直し始めて往復する**型が、09/14 と FV で2回起きた。次に FV・トップを触る時は、**直す前に基準を書く**ことを最初の一手にすると、手戻りが最も減る。
