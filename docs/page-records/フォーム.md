# フォーム(内見予約・問い合わせ・査定依頼・管理相談)

問い合わせの4本。実装順 5(2026-09-15〜)。**① `/viewing` 内見予約・② `/contact` 問い合わせ・③ `/sell` 査定依頼(フォーム部分のみ・09/17)は実装済み。④ `/owner` 管理・空室相談は未着手。**

このサイトは制作の記録を残すための架空のサイト。会社名・住所・電話番号・免許番号・人名・物件はすべて架空で、番地は `0-0-0`、電話は `03-0000-0000`、免許番号は `000000` に統一している。**フォームの送信内容は実際の対応には使われない**(その旨をフォーム上部・完了画面・自動返信メールの3箇所に出す)。

判断の経緯は `docs/記録シート.md` の J-007・J-102〜J-106、失敗は F-011。項目の正は SHIN の項目表(09/16)で、一覧は `.claude/rules/forms.md` §1 にある。ここでは**①② で何ができるか**と、**③④ に入る時の前提**を書く。

## できていること(①②)

| URL | 何のフォームか | 対象物件 |
|---|---|---|
| `/viewing` | 内見予約。**物件が必須**で、`?property=HR-R-0001` から自動で表示する。無い・形が違う・成約済みのときは `/contact` へ移す(注記は出さない) | 必須 |
| `/contact` | 問い合わせ。種別(空室確認 / 質問 / 来店予約 / 法人 / 採用)を `?kind=` で初期選択できる。**内見希望は含めない**(`/viewing` に分けたため) | 任意。無いときは「物件を指定せずに送ります」と案内を出す |
| `/sell` | 査定依頼(J-107)。物件種別で**築年・間取りの欄が出入りし**、面積のラベルが変わる(専有 / 建物 / 土地)。所在地は区の選択+自由入力で、対応エリア外(その他)も受ける。フッターの `/sell#form` で**フォームの先頭に着地**する | 持たない。右カラムは「査定の進み方」(03 §7・v0.88) |

**流れは3画面とも同じ URL**:入力 → 確認 → 完了。確認画面を挟むのは不動産の慣習に合わせたもの。「修正する」で入力に戻れる。送信内容は完了画面に出さない。

- **共通の入力**:お名前(必須)/ ふりがな / 電話番号(必須)/ メール(任意。入れた人にだけ自動返信)/ 希望連絡方法(電話・メール・LINE)/ 備考 / プライバシーポリシー同意(必須)
- **備考のラベルは場面で変える**。`/contact` は種別に合わせて「ご質問の内容」「ご希望の日時」などに変わり、質問・来店予約では必須になる
- **水曜(定休)の希望日は選べなくしない**。選んだときに確認画面で注記を出す
- **完了画面**:「送信しました」+ 架空注記 + 折り返しの目安(翌営業日まで)+ 電話番号 + 導線。導線は**同じ形のボタン2つ**で、主が「物件を探す」・副が「トップへ戻る」(1280 は横並び・390 は縦積み)
- **スパム対策**は Cloudflare Turnstile。**トークンが入るまで「送信する」は押せない**(文言は「確認を準備しています…」)。送信中も押せない
- 担当者名は出さず部署名まで。送信データは SHIN 宛にだけ届き、どこにも保存しない

## ③ `/sell` ④ `/owner` に入る時の前提

**①② で決まった構造のうち、③④ が踏襲するもの。** 新しい作り方を足さない。

### 1. 分ける物と共有する物(J-007 → J-105)

- **UI と Server Action の流れは4本とも別実装**。工程を4回通して比べることが記録の目的なので、`ViewingForm` `ContactForm` を共通化しない(見た目が同じでもコピーして持つ)
- **共通化するのはロジックと I/O だけ**:`lib/forms/common.ts`(共通項目の型・読み取り・部分スキーマ・確認行)/ `dates.ts`(日付)/ `deliver.ts`(Turnstile と Resend)/ `resolve-property.ts`(対象物件の再解決。③④ は使わない)。各モジュールの中身と Zod の足し方は `.claude/rules/forms.md` §3-A
- 固有のロジックは `web/src/lib/sell.ts` `owner.ts` に置き、**同じコミットに `sell.test.ts` `owner.test.ts` を入れる**(J-041)

### 2. ページの形(03 §7・J-103)

- `page.tsx` は Server Component。**`searchParams` を読まない**(読むとルートが Dynamic になる)。クエリはクライアントが `useSearchParams` で読み、`<Suspense>` で包む
- 1024 以上の2カラム(3fr / 2fr・gap 32)は `page.tsx` 側が持ち、フォームのコンポーネントが**3つの子**(H1と注記 / 右カラム / フォーム)を返して置き場所だけ指定する。1023 以下は DOM の順に縦へ積む
- **③④ は対象物件を持たない**ので、右カラムに何を置くかを着手前に決める(①② は対象物件の要約を置いた。空にするなら1カラムに寄せる判断が要る)
- **`/sell` `/owner` は説明とフォームを同じページに置く**(フッターの導線が `/sell#form` `/owner#form` で、ヘッダー・フッターの `/sell` `/owner` は既にある)。**説明の部分は実装順 6 と重なる**ので、どちらで書くかを先に決める

### 3. 環境変数と送信(J-105・F-011)

- `RESEND_API_KEY` / `CONTACT_EMAIL_TO` / `TURNSTILE_SECRET_KEY` が無いとき、開発では飛ばして完了まで通し、**本番では拒否する**。この分岐は `deliver.ts` の中にあるので各フォームで書かない
- 送信元がサンドボックス(`onboarding@resend.dev`)の間は**自動返信を送らない**
- **`.env.local` を変えたら再ビルドしてから 3001 を立てる**。静的ページの環境変数はビルド時に焼かれる(F-011:site key が空のまま焼かれ、送信が通らなかった)
- メールは `@react-email/render` で html と text を作って渡す(`react:` prop は使わない)

### 4. 着手前に決めること(①② で聞かれた種類)

- **項目の正は SHIN の項目表**。01 と食い違うときは項目表が正(①② の4点の差分がそれ)。項目を増やすときは J-ID
- ③ 固有:査定の種類(机上 / 訪問 / 相談してから)・所在地は区の選択+町名以下は自由入力(**対応エリア外も受ける**)・**土地のときは築年と間取りを出さない**
- ④ 固有:相談内容から**売却を外し**、上部に「売却をご検討の方は査定依頼へ」のリンクを置く
- 宛先の部署名は `config/forms.ts` の `DEPARTMENT` に **③④ の分を足す**(今は viewing / contact の2つだけ)
- 完了画面・自動返信の文面の型(架空注記 → 折り返し → 電話 → 導線)は①②と同じにする

### 5. 確認のしかた

- 3001 で静的ビルドして測る(`.claude/rules/verification.md`)。**390 → 1280 の順**に見る
- 自動で完了画面まで進めるときは、**送信ボタンが押せるようになるまで待ってから押す**(トークンが1〜2秒遅れる)
- 残っている未確認:Turnstile の実表示と検証(本番キー)/ Resend の到達・不達・迷惑メール判定(SPF・DKIM)/ `outputFileTracingIncludes` が Vercel で効くか(Action が実行時に index.json を読むため)
