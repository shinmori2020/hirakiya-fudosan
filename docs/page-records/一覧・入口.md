# 探し方の入口と条件固定の一覧

エリア・沿線・駅・特集から物件を探すためのページ群。入口3ページと、条件を1つ固定した一覧38ページからなる。実装順 4(2026-09-15)。

このサイトは制作の記録を残すための架空のサイト。会社名・住所・電話番号・免許番号・人名・物件はすべて架空で、番地は `0-0-0`、電話は `03-0000-0000`、免許番号は `000000` に統一している。

判断の経緯(なぜその形にしたか)は `docs/記録シート.md` の J-095〜J-099 にある(一覧そのものの作りは J-033〜J-046)。ここでは**何ができるか**だけを書く。

## ページの一覧(41ページ)

| URL | 数 | 何のページか |
|---|---|---|
| `/area` | 1 | エリアから探す。4区13町を件数つきで並べる |
| `/line` | 1 | 沿線・駅から探す。6沿線13駅を件数つきで並べる |
| `/feature` | 1 | 特集から探す。6特集を説明文と件数つきで並べる |
| `/area/[slug]` | 13 | 町で絞った一覧(青戸・立石・お花茶屋・亀有・新小岩・金町・堀切・小岩・平井・綾瀬・北千住・押上・曳舟) |
| `/line/[slug]` | 6 | 沿線で絞った一覧 |
| `/station/[slug]` | 13 | 駅で絞った一覧 |
| `/feature/[slug]` | 6 | 特集で絞った一覧 |

**`/properties`(条件を自由に選ぶ一覧)との関係**:38ページは `/properties` と**同じ部品**(左カラムの絞り込み・ドロワー・クイック条件タブ・条件タグ・並び替え・ページ送り・カード・0件画面)を使い、**条件を1つだけ固定した状態**で開く。固定した条件以外はすべて `/properties` と同じように変えられる。売買専用の一覧は作っていない。**売買は `/properties` も38ページも「売買」タブ(`?type=sale`)で切り替える**。

1ページに20件、それを超えるとページ送りが出る。並び替えは 新着順 / 家賃(価格)が安い順 / 高い順 / 広い順。成約済みは並び替えに関わらず末尾に回る。

## 入口ページ(/area /line /feature)

**共通の作り**
行は「名前(太字)」と「賃貸 ○件 / 売買 ○件」の3つのリンクでできている。名前と「賃貸 ○件」はその条件で絞った一覧(賃貸)へ、「売買 ○件」は同じ一覧の売買へ移動する。行の間は細い線で区切る。カードも地図も使わない。

- **件数は賃貸と売買で分けて出す**。数え方は一覧の件数表示と同じで、**成約済みも含む**(入口で「4件」と見て押した先が「3件」にならないようにしている)
- **0件の町・駅・特集もそのまま「0件」と出し、リンクとして残す**。押した先の0件画面が、条件を緩める候補や近隣エリアを案内する
- 押せるものは青緑の文字で、下線はホバーしたときだけ出る(物件詳細と同じ扱い)
- `/area` と `/line` は 768px 以上で2列、`/feature` は常に1列

**/area(エリアから探す)**
区を見出し(葛飾区7町 / 江戸川区2町 / 足立区2町 / 墨田区2町)にして、その下に町の行を並べる。町名と並び順は `web/src/config/site.ts` の `serviceAreas` から取り、slug はタクソノミー `area` の町名と突き合わせて引く。**突き合わない町名は行そのものを出さない**(13町の外へ出ないため)。区そのもののページは無い(`/area/katsushika` は404)。

**/line(沿線・駅から探す)**
**沿線6本とその駅を最初からすべて表示する。開閉はしない。** 沿線の見出し自体がその沿線で絞った一覧へのリンクで、右に沿線の件数が付く。その下に駅の行(「青砥駅」のように「駅」を付ける)が並ぶ。

**同じ駅が複数の沿線に属する場合は、それぞれの沿線の下に出す。** 北千住・押上・金町・青砥の4駅が該当し、13駅に対して行は延べ17行になる。飛び先はどちらから押しても同じ `/station/[slug]` で、その駅を最寄りとする物件がすべて出る(沿線では絞られない)。左カラムの駅チップが「複数路線の駅は最初の沿線にだけ置く」のとは扱いが違う。左カラムは同じ駅を2回選べないようにするため、入口は「この沿線にはこの駅がある」を示すためで、目的が異なる。

| 沿線 | 駅 |
|---|---|
| 京成本線 | お花茶屋・京成小岩・堀切菖蒲園・青砥 |
| 京成押上線 | 京成立石・押上・青砥 |
| 京成金町線 | 金町 |
| JR常磐線 | 亀有・北千住・綾瀬・金町 |
| JR総武線 | 平井・新小岩 |
| 東武スカイツリーライン | 北千住・押上・曳舟 |

**/feature(特集から探す)**
6特集を 02 の並び(都心まで30分以内 / 敷礼ゼロ / ペット可 / 戸建賃貸 / 駅徒歩5分 / 新築・築浅)で出し、各行の下に**説明文**を添える。説明文は `web/src/config/site.ts` の `collectionDescriptions` に置いてあり、その特集の絞り込み条件を説明するに留める(閑静・人気など、物件データに無い形容は書かない)。

特集のうち **「新築・築浅」だけは物件に保存せず、読み込み時に築年月から判定している**(築5年以内)。時間の経過だけで対象が出入りするため。築年月が無い土地は対象に入らない。他の5つは物件に保存された値をそのまま使う(02 §2)。

## 条件固定の一覧(38ページ)

**固定条件の持ち方**
固定した条件は **URL のクエリに書かない**。パス(`/area/aoto`)が持ち、画面を組み立てるときに条件へ足し、URL を書き換えるときに落とす。そのため左カラムで家賃を変えても URL は `/area/aoto?rent_max=90000` のままで、`area=aoto` が二重に付くことはない。`/area/aoto?area=tateishi` のような矛盾した URL も作れない。

**左カラム(PC)とドロワー(スマホ)**

| 固定したもの | 左カラムの見え方 |
|---|---|
| 町 | 「エリア」の区分が **「葛飾区青戸(このページの条件)」+「他のエリアから探す」** に置き換わる。駅・家賃・間取り・詳細条件はそのまま使える |
| 駅 | 「駅」の区分が **「青砥駅(このページの条件)」+「他の沿線・駅から探す」** に置き換わる。エリアの区分はそのままなので、駅ページの中でさらに町で絞れる |
| 沿線 | **駅チップがその沿線の駅だけになる。** 沿線名の後ろに「(このページの条件)」が付き、下に「他の沿線・駅から探す」 |
| 特集 | 左カラムに特集の区分は無いので変わらない(クイック条件タブ側で対応する。下記) |

**固定した条件は変更できない。** ×付きの条件タグにも出さず、「絞り込み(n)」の n にも数えない(変えられる条件だけを数える)。ドロワーや0件画面の「条件をすべてクリア」を押しても**固定条件は残る**。

**クイック条件タブ**
特集で固定したページでは、**その特集のタブと、slug が同じ設備のタブを出さない**。押しても結果が1件も変わらないため。該当するのは ペット可(特集 `pet-ok` / 設備 `pet-ok`)と 敷礼ゼロ(特集 `zero-deposit` / 設備 `敷金礼金ゼロ`)の2組で、判定は slug の一致だけで行う(件数では判定しない)。エリア・駅・沿線で固定したページのタブは減らさない。

**左カラムの設備・条件**
特集で固定したページでは、**左カラムの「詳細条件 → 設備・条件」にある同じ条件の項目**(`/feature/pet-ok` の「ペット可」、`/feature/zero-deposit` の「敷金礼金ゼロ」)を**チェック済み・変更不可**で出す。消さずに残すのは、左カラムだけを見て何で絞られているかが読み取れるようにするため。ラベルの後ろに「(このページの条件)」が付き、キーボードの移動先からは外れる。上位6つの外にある設備(敷金礼金ゼロ)も、固定なら「もっと見る」を開かずに出す。

**見出しとパンくず**
h1 は「葛飾区青戸の物件」「京成本線の物件」「青砥駅の物件」「ペット可の物件」のように**種別(賃貸 / 売買)を含めない**。種別は URL のクエリで切り替わるものなので、静的な HTML の見出しには入れられない。駅のページは h1 の下にその駅が属する沿線名、特集のページは特集の説明文を出す。

パンくずは**3階層**(トップ > エリアから探す > 葛飾区青戸)で、ここにも種別は入れない。駅のページは「トップ > 沿線・駅から探す > 青砥駅」で、**沿線は階層に入れない**(駅が複数の沿線に属するため、1本を選べない)。

**種別の切り替え**
賃貸 / 売買のタブは同じページの `?type=sale` を出し入れする。**切り替えたときに他の条件は持ち越さない**(`/properties` と同じ動き)。

**生成**
38ページとも `generateStaticParams` で全件を列挙して静的な HTML を生成する。一覧に無い slug は404(`dynamicParams = false`)。町のページは区の slug を除いた13件、沿線は `config/site.ts` の `lines`、駅と特集はタクソノミーから列挙している。ページごとに title と description を出している(構造化データは実装順 8)。

## 0件のとき

条件に合う物件が無いときは「該当なし」で止めず、次の順に案内する。

**1. 条件を1つ緩める候補(件数つき)**
外すと1件以上になる条件を、**駅徒歩 → 築年数 → 面積 → 設備 → 特集 → 間取り → 種目 → 家賃 → 価格 → エリア → 駅 → 沿線** の順に並べて出す。どれを1つ外しても0件なら、同じ順に累積して外し、初めて1件以上になった組み合わせを1つだけ出す。

**このページで固定している条件は候補に出さない。** 例えば `/area/aoto` で「エリアの条件を外す」は出さない(押しても青戸から出られないため)。

**2. 近くのエリア(件数つき)**
選んでいる町と**同じ区の他の町**だけを、他の条件を保ったまま数えて出す。0件の町は出さない。13町の外には出ない。町で固定しているページでは、条件を書き換えるのではなく**その町のページ(`/area/[slug]`)へのリンク**になり、他の条件はクエリで引き継ぐ。

**3. どちらも無いとき**
「条件をすべてクリア」(固定条件は残す)を出す。**固定条件だけで0件**のとき(その町に売買物件が無い場合など)はクリアするものが無いので、代わりに入口ページ(「他のエリアから探す」など)へのリンクを出す。

## 純関数とテスト

条件の計算は `web/src/lib/` に純関数として置き、隣に同名のテストを置いている(`web/data/` は読まず、最小のダミーで検証する)。

| 関数 | 何をするか |
|---|---|
| `applyFixed(q, fixed)` | URL から読んだ条件に、パスが持つ固定条件を足す |
| `stripFixed(q, fixed)` | URL に書く前に固定条件を落とす |
| `relaxCandidates(all, q, now, fixed)` | 0件時に緩める候補を作る。`fixed` の条件は候補から外す |
| `nearbyAreas(all, q, areaTerms, wards, now)` | 同じ区の他の町を、他の条件を保ったまま数える |
| `hideFixedTabs(groups, fixed)` | 固定した特集と同じ条件のクイックタブを落とす |
| `collections.ts` `isNewBuilt` / `collectionsFor` | 「新築・築浅」を築年月から判定し、読み込み時に特集を付け直す |
| `entries.ts` `countBy` / `entryCounts` | 入口ページの件数(賃貸・売買別・成約済みを含む) |
| `entries.ts` `townsByWard` | 区ごとの町。タクソノミーに無い町名は落とす |
| `entries.ts` `stationsByLine` | 沿線ごとの駅。複数の沿線に属する駅はそれぞれの下に出す |

テストは全体で145件(`pnpm test`)。

## 検証

`web/scripts/check-entries.mjs` が、3001 で起動した本番相当のサイトに対して3点を検査する(`node scripts/check-entries.mjs`)。

1. **入口ページに出ている件数と、そのリンクを押した先の一覧の件数が一致するか**
2. **入口ページから出ていくリンクがすべて 200 を返すか**(未作成ページへのリンクが残っていないか)
3. **条件固定の一覧で条件を変えた後の URL に、固定キー(`area=` / `line=` / `station=` / `collection=`)が入っていないか**

物件詳細で使う `check-fields.mjs` は JSON のフィールドを起点に1ページの中を検査するので、ページとページの関係は見られない。そのため別のスクリプトにしている。ページが増えたらスクリプト冒頭の `ENTRIES` に足す。

## データと生成

物件60件(賃貸40・売買20)とタクソノミー(町・沿線・駅・設備・特集)は WordPress(ローカルのDocker)から JSON に書き出したもので、ビルド時にそれを読んで41ページすべてを静的な HTML として生成している。件数もビルド時に数えた値で、公開後にサーバー側で組み立てる処理は無い。物件の絞り込みと並び替えはブラウザ側で行う。
